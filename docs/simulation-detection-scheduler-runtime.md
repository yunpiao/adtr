# 合成检测计划运行边界（SIM-SCHEDULE-001）

本页记录模拟开发假设，不是原产品依据、真实 AD 证据或产品验收。
对应 Issue #41（AD-F-079/080）及 #15（AD-F-190）的合成检测切片。

## 显式接入

迁移 27 仅经 `adtr -mode migrate` 的既有原子迁移入口执行；运行时不建表。
它增加独立计划/版本/回执/发生记录与 `simulation_detection_schedules` 权限定义，
不向任何现有角色插入授权。历史迁移 26 与健康计划契约保持不变。

以下两个开关必须同时精确为 `true`，API 才接受新计划请求，Worker 才注册
`simulation.detection.scheduled` 并运行独立调度循环：

- `ADTR_SIMULATION_DETECTION_ENABLED`：既有合成检测功能开关。
- `ADTR_SIMULATION_DETECTION_SCHEDULES_ENABLED`：新增未来执行能力开关，默认关闭。

第二个开关是防止仅启用手动检测时意外开始周期任务的必要隔离；删除或留空将
禁用新计划入口、任务种类与调度循环，但不删除已有计划、意图或历史。
开关不授予权限。接口、领取、执行与结果发布仍检查当前用户、域和双重独立授权。
暂停运行环境的开关不承诺取消已在另一 Worker 执行的任务。

新种类故意不标记通用 `Schedulable`：它用独立 occurrence intent 与普通
`SubmitTx` 原子关联，保留最终发布 `ValidateSuccess` 门禁。健康计划仍仅允许
原来的健康任务；手动检测仍要求原来的手动回执，没有共享 OR 旁路。

## 新模块调度预算与生命周期

仅新循环每次 Tick 使用最长 5 秒的子 context，立即执行第一轮，正常轮次间隔
1 秒。轮次失败只输出固定错误描述；等待按 2、4、5 秒增长并封顶，成功恢复
1 秒。它不改变任何旧任务租约、心跳、重试次数、旧调度器或 CI deadline。

5 秒上限限制一次数据库异常占用；无此上限会延长当前轮次等待和停机响应。
代价是数据库缓慢时本轮可能回滚，下一轮重新检查。同一发生记录的唯一约束与
原子意图防止把重试变成重复提交。60 秒迟到窗口、每轮最多 32 个候选属于新模块
语义/容量边界，不能解释为真实网络吞吐率；持续负载下可能产生明确的错过记录。

根 context 取消同时中断当前 Tick 和退避等待；Worker 退出先取消再等待新循环
结束，之后才进入既有清理流程。未同时开启两个开关时不会创建该循环。
没有操作系统 cron、远程调度器或部署配置；本改动不执行部署。

## 界面与结果说明

导航仅在会话同时具有 `simulationDetectionReadable` 和
`simulationDetectionSchedulesReadable` 提示时显示，提示不是授权；页面与 API
重新核验权限。字段缺失默认为隐藏，旧会话不会推断获得新能力。

真实 PostgreSQL、API/Worker、浏览器证据须由独立运行记录补充。
单元测试或带 integration 标签的仅编译不能登记为 PostgreSQL 执行通过。
