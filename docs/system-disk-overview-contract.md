# 系统信息页的 API 根文件系统观测

关联 [F52 / Issue #14](https://github.com/yunpiao/adtr/issues/14) 的
AD-F-196、FLD-3154。原字段仅定义 `status.diskUsagePercent` 为磁盘使用百分比
小数，没有声明全部宿主机磁盘、空值默认值或此卡片的样式。
本切片采用已有 [系统监控契约](system-health-contract.md) 的明确运行范围，
补充系统信息页展示，不把该运行范围或两位小数格式称为原系统 1:1 验收要求。

## 数据与状态

卡片只读取已有 `/api/system/info` 结果的 `current.snapshot.storage`，
选择唯一的 `id=runtime-root`。其固定注册目标是 API 进程看到的 `/`，来源
`statfs`、范围 `runtime_filesystem`；不是宿主机全部磁盘、PostgreSQL
数据卷或容器磁盘配额。来源、范围及采样时间随原观测显示，时间统一为 UTC。
实际来源字面值依据 `internal/systemhealth/sampler.go` 的采样实现；组件透传
观测元数据，不将既有 DOM 夹具中的 `linux_statfs` 别名当作真实服务端输出。

仅在整份 `current` 的 `stale=false`、`availability=available`，且唯一磁盘
指标 `availability=available`、`percent` 非 null 时，突出显示当前百分比并标记
`data-state=observed`。沿用两位小数格式；真实 0 和 100 分别显示 0.00% 与
100.00%。百分比来自现有 statfs 契约 `used/(used+free)*100`，不在页面重算。

无快照、无目标、重复目标、不可用指标或 null 均显示“当前使用率未知”，
标记 `data-state=unknown`，不补零、不代用其他目标或数组首项。
整份观测陈旧或不可用时，即使磁盘指标自身可用，也不能当作当前值；保留的
数值只以“已有观测”标注，并明确不代表当前使用率。服务器的 `clock_skew`
同样使当前值未知，显示时钟证据不一致和核对建议；不增加客户端时钟判定。
未知状态提供相应缺测、重复目标、读取失败或采样过期的说明与处理建议，
不把建议写成已验证的具体故障根因。

`current` 是组件唯一必需输入，传入现有系统信息读结果，用于同时判断整份观测
与单项指标。缺失输入不能渲染该组件；省略新组件只失去此概览展示，不改变
底层采样或存储页。复用已有卡片样式，没有新增部署配置、API、轮询、持久化、
设置操作或权限；现有系统读取授权、会话失效与读取失败清理仍由工作区负责。
仅新增只读展示，副作用是系统信息页增加一块卡片；资源、历史与存储设置不变。

## 验证边界

独立组件 DOM 用例覆盖可用值与来源、两位小数、0/100、陈旧、整份不可用、
服务器未来时钟拒绝、磁盘读取失败/null、无快照、缺失/重复目标、非首目标
及恢复后的值替换。每次测试复制独立夹具，避免对象共享污染其他用例。
工作区接线、读取授权、失败清理与会话回归由集成方另行验证。

旧本地候选与历史 CI 的通过不能作为当前候选证据。当前执行命令和结果保存在
候选外证据包；DOM 与类型检查不能替代真实浏览器、PostgreSQL、独立审查或
精确 head CI。无部署，Issue #14 保持开放，产品验收仍为 0/209。
