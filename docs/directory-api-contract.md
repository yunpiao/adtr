# Directory API contract for the local UI slice

All routes use existing authenticated same-origin cookie/CSRF machinery, error JSON `{error: code}`, no-store responses and `X-ADTR-User-ID`. Mutations require current password and one-time TOTP proof. No password, TOTP or account credential enters persisted browser recovery state.

- GET /api/directory/observation: exact query domainId (required), observationId (optional), kind (optional user/group/computer), pageIdx (default1), pageSize (default50;25/50/100). Page>1 requires observationId from the first page. Response `{available,observationId?,source?,list,page}`; page fields pageIdx,pageSize,total,totalPage. available=false means no current successful observation; available=true/list=[] is an observed empty result. Objects have objectGUID,distinguishedName,kind,objectClass:string[],samAccountName:string|null,userAccountControl:number|null. Source has server_name,dc_host_name,domain,naming_context,started_at,completed_at,elapsed_milliseconds,pages. Timestamps RFC3339 UTC. Stable ascending GUID ordering after kind filter. Refresh/domain/kind change resets page and snapshot pin. Stale pin returns409 directory_observation_unavailable; reload first page explicitly.
- POST /api/directory/sync: exact body domainId,expectedRevision,expectedCredentialGeneration,idempotencyKey,actorPassword,totpCode. All revision and key fields are strings. Reuse the configured-domain picker: SourceChoice.revision→expectedRevision; credentialRevision→expectedCredentialGeneration. Backend initially requires an already-bound operation account; custom/unconfigured source returns409 directory_account_required. Response existing tasks.Submission `{task,replayed}` with standard public task shape.
- GET /api/directory/receipt: exact domainId,idempotencyKey; returns `{task}` for current actor's own directory intent, with live permissions. Recover unknown outcome before resubmitting; retain original intent/pins/key, never automatically issue a new write.
- GET /api/directory/task: exact taskUUID; returns `{task}` for current directory task/domain scope. No object bytes or credential pins in generic task metadata.
- POST /api/directory/cancel: exact taskUUID,actorPassword,totpCode; returns `{task}`. Acceptance does not prove the worker stopped or release credential blockers. Display actual task state.

Read observation requires domains.read +directory_assets.read. Receipt/task also require tasks.read. Writes require domains.read +directory_assets.read/write +tasks.read/write; domains.write and operation-account metadata read are not prerequisites. Introspection is via the existing access API. Reader data visibility is independent of permission to use credentials; explicit directory-purpose use grant is still mandatory for synchronization.

Directory grant administration uses /api/directory-credential-use with the existing seven credential-use suffixes, request/response shapes and proof/receipt semantics. Its exact purpose is domain.directory_read. The original /api/credential-use remains domain.connection_test only. All new grant routes except /effective require builtin platform_admin. /effective requires domains.read +directory_assets.read and current scope. No existing grant is copied or implied. Keep recovery buckets and labels distinct by purpose.

Runtime ADTR_DIRECTORY_READ_ENABLED defaults false and may cause503 directory_read_disabled. Capable compiled consumer does not mean deployment access is enabled. Initial data only contains the bounded dictionary above; no incremental sync, deletions, memberships, ACLs, IP mapping or source parity claim. A successful bounded observation is not an AD point-in-time snapshot. Schema/producer/browser/AD runtime evidence remains separately tracked.
