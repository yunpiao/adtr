# F40 批量已读界面与原操作恢复

关联工程 #115、#50 / AD-F-158 / DTL-036。依赖已合并 PR #113 的 schema18 接口；不修改 schema、Worker 或授权规则。保留 PR #109 单条已读、固定查询与原真实浏览器链。完整 F40、源系统兼容及产品验收仍开放。

## 选择与确认

- 同一 `resultId` 的跨页选择保留；草稿筛选修改不改变当前固定结果或选中集合。新结果替换后选择与旧预览不再可提交。
- “选择固定结果全部”仅指当前固定结果的全部列表成员，包含全部页和查询时已读项，不重新查询全库。模式为 `all` 时不发送 `messageIds`；`selected` 按固定选择 ID 集合提交。
- “预览批量目标”展示固定结果、范围、目标数及所选 ID；第二次显式“确认启动批量已读”才分配一次操作 ID，可靠持久化并读回后发出请求。重复点击、未知结果、恢复中和不可用存储都不能产生替代批次。
- 新操作仍受原固定结果会话、有效期和权限版本约束；页面不把过期结果偷偷换成新结果。新查询与批次恢复互相独立。

## 持久进度与状态

服务端回执固定 `operationId/resultId/selection/acceptedAt/target`。浏览器核验原请求和目标数、完整字段、有效 UTC、整数范围、计数守恒与进度单调性。已有终态不能变回活动态，原接受回执不能改变。

- `Target = Processed + Remaining`
- `Processed = NewlyRead + AlreadyRead`
- `Failed = 0`：数据库错误回滚整批，未提交项仍是 Remaining，并在后台重试，不能假造逐项业务失败。

状态分别解释为：queued 已接受但未提交第一批；running 有已提交进度且仍有余项；completed 所有目标处理完；cancelled 已确认取消余项；authorization_blocked 原授权条件或版本失效，余项停止。后二者的 Remaining 可大于零，这些余项不会由原操作继续执行。重新授权不复活原权限阻断终态。

界面显示全部六项持久进度和已核实/待确认区别。批次不会修改旧快照的成员、序号、阅读状态或计数；用户显式“确认查询”后才看到新结果。

## 未知响应与取消

- start、cancel 的丢响应、异常正文或超时均保留原意图，不能当作失败或成功。恢复只 GET 原 operationId，不自动发出任何 POST。
- 查不到原操作的 404 不证明原提交未发生。只有用户显式点击重放才再 GET 一次；仍 404 后才用同 ID、同结果和同目标重放。
- 取消前先 GET 原操作；如果已终结直接显示终态，否则只 POST 原 operationId。再次取消仍是对同一操作的幂等请求。
- 取消响应未知时，查询仍 running 只代表查询时观察，不证明原取消一定没提交；可显式再次请求同批取消，不生成新批次。
- 取消只停止尚未提交余项，保留已经提交的首次已读时间与逐项原收据。

## 本浏览器恢复与身份隔离

独立 `adtr.message-bulk.v1` 键只保存 owner ID、username、原请求和目标数。它与单条 `adtr.message-read.v1` 分开；不保存消息正文、计数回执、密码、MFA、CSRF、cookie 或 session 绑定。每操作一键，其他标签的原意图不能被覆盖。

刷新、关标签重新打开和同用户新会话均先复核当前读取授权，再读取本人保存意图，通过 GET 恢复服务端真实进度。已接受操作的查询不依赖旧快照有效性。终态保留本机恢复记录直到用户“收起已结束批次”；此按钮只清理本地发现记录，不删除服务端收据。

身份或 CSRF 会话变化会重挂会话组件，旧请求被中止；当前身份/权限失效时立即清空可见私有结果并废弃请求代次。迟到响应不能重新显示旧用户批次或触发旧意图。403/401 不自动绕过或重放；再次获准时仍只恢复原操作。

本机存储损坏、不可写或读回不一致时关闭新提交入口，不覆盖未知原记录。其他用户命名空间既不显示也不执行。此版本没有跨设备批次发现 API；清除浏览器存储会失去本机发现索引，但不取消服务端操作。

## 有界恢复设置及作用

这些是本模块固定值，不新增部署配置：

- 获准恢复后立即首查，后续每 2 秒只读轮询：以最后查询的操作 ID 选择字典序后继，末尾回绕；终态退出候选或本地收起不会使可变数组下标跳过待查项。每次只发一个 GET，已有请求在途时跳过该轮，不追加并发或补发积压 tick；storage/focus 发现新意图仍等待下一轮。GET 可安全自动重试；没有自动 start/cancel 重放。删除立即首查会额外增加首轮等待，删除轮询会要求用户手动恢复进度；副作用是每次获准挂载多一个即时读取，持续频率仍有界。网络耗时和 15 秒等待上限影响实际恢复时间，不承诺 5 秒内完成所有批次。
- 15 秒整次请求等待上限：超时停止等待、废弃该代次并解除界面锁，原 ID 保持，后续只读查询。它不取消后端操作。删除会使永不 settle 的网络请求永久禁用所有操作按钮；缩短可能增加未知响应提示与 GET 流量。
- 1000 目标继承服务端查询/冻结上限；32 KiB 请求字节限制在新提交前检查。ID 总字节超限时不发送，可减少选中项或使用固定结果 all。上限是工程保护，不是容量/P95 承诺。
