# ADTR 总体技术方案

状态：待评审。本文将 209 项需求组织为可持续交付的 AD 安全平台设计，保留模块化单体 API、独立 Worker 和 PostgreSQL 权威存储，先完成权限与可信采集，再逐步形成检测、调查、响应和报告闭环。原型用于确认流程，不作为真实 AD 能力的证明。

基线、状态定义和阅读入口见[方案索引](README.md)。未特别标明“现有”的内容均为拟议产品组织或后续实现要求。现有 API 的精确字段和错误码以其关联契约为准；本文不注册新路由、任务或权限。

## 1 产品定位与范围

ADTR 面向负责 Active Directory 安全的调查人员、检测规则人员、响应人员和平台运维人员。核心问题是将分散的域、目录资产、事件和安全发现归入受授权的上下文，让使用者知道数据来自哪里、是否新鲜、为何被判断为风险、可以执行什么动作以及执行结果是否确定。

### 1.1 全量范围

[需求台账](../../requirements/catalog.json)保留全部 AD-F-001 至 AD-F-209，按 57 个功能组交付。P0/P1/P2 只表示实施顺序，任何优先级都不能从最终范围移除。逐项入口见[追溯表](requirements-traceability.md)。

产品覆盖 AD 接入与部署、采集和目录资产、检测与规则、事件调查和攻击路径、响应与白名单、行为检索、报告与导出、消息通知、身份与权限、后台任务、系统运维及安装发布。不能以同名菜单、统计卡、静态图谱或通用任务框架代替这些业务实现。

### 1.2 现有能力与未交付边界

基线 [README](../../README.md)、[交付台账](../delivery.md)和代码共同表明：本地账户/MFA、用户角色功能权限、资源授权、持久化任务、平台审计、健康监控、有限周期计划、域配置与单次诊断、操作账户登记、审计导出、运行日志及受限目录读取已有切片。React 页面位于 [web/src](../../web/src)，这不是独立的产品原型。

域读取默认关闭。v1 与 v2 具有独立开关、授权及凭据用途；v2 新增四类事实字段的合成链路验证不等于 F14 业务资产页面、完整字段、关系和导出全部完成。见 [v2 整合状态](../directory-v2-integration-status.md)。

真实 AD/Windows、采集器全生命周期、增量采集、检测算法、阻断执行器、生产部署及 209 项产品验收仍未完成。本文不承诺迁移历史源系统的缺陷或弱安全行为。

## 2 角色与工作闭环

角色是用于设计的工作视角，最终权限必须落实到已有 F45/F46/F47 的动作与范围矩阵，不能把角色名称硬编码为数据通行证。

| 工作视角 | 主要工作 | 关键限制 |
| --- | --- | --- |
| 安全调查 | 看资产、发现、事件、证据和历史；提出处置建议 | 仅读取获授权租户/域，导出另行检查权限 |
| 检测规则管理 | 编写/测试规则、发布版本、配置检测模板 | 编辑不自动拥有发布或响应权；规则输入依赖 G04 |
| 响应操作 | 对明确对象执行已授权阻断/恢复并核对结果 | 新鲜验证、作用域、白名单、影响确认与审计；未知结果不能盲重试 |
| 平台管理 | 用户、角色、资源组、连接、账户、许可 | 平台管理员不默认拥有 AD 数据或凭据使用权 |
| 运维与审计 | 看健康、任务、诊断包及操作记录 | 运维入口与业务响应分权；看日志不等于能重启或删除数据 |

### 2.1 关键闭环

1. 接入：创建域配置 → 明确授权域范围 → 登记账户引用及用途 → 单次连通诊断 → 查看结果与时间 → 配置采集。现有单次诊断通过只证明该次探测，不证明采集在线或有目录读取授权。
2. 调查：选择授权域/时间 → 定位资产或事件 → 查看来源、证据和关联 → 标记/分配处置 → 跟踪状态 → 形成报告。后半段调查业务仍需实现；不能从当前目录列表推断已有完整调查链。
3. 检测：选择模板/规则版本与目标 → 预检授权及输入 → 提交 → 任务进度 → 部分失败/失败解释 → 查看结果 → 复查或报告。规则结果必须有可判定夹具。
4. 响应：事件/对象 → 操作候选 → 影响和白名单预检 → 新鲜验证/确认 → 受限执行 → 确定结果或待核对 → 可用时按新任务恢复。取消请求不等于撤销已发送动作。
5. 运维：健康异常 → 关联任务/连接/日志 → 查时间窗 → 生成诊断包 → 核对恢复。旧健康样本和未知状态不得显示为正常。

## 3 导航与交互设计

### 3.1 拟议导航

固定左侧导航、顶部授权域/时间上下文、主体列表/工作区及对象详情。顶栏的范围展示是过滤上下文，服务端仍独立授权；“全部”只表示当前可见范围。

| 导航 | 功能组 | 页面组织与主要对象 |
| --- | --- | --- |
| 安全总览 | F36 | 风险、检测、事件和覆盖率；注明数据时间与缺失 |
| AD 接入 | F01–F11 | 域、域控、账户引用、采集器、部署与采集诊断 |
| 目录资产 | F12–F17 | 资产列表/详情、关系、ACL变化、敏感标记、身份风险 |
| 检测与规则 | F18–F28 | 检测任务与结果、规则版本、学习配置、模板、白名单 |
| 威胁调查 | F29–F30、F33–F35 | 事件、证据、攻击路径、行为检索、蜜罐配置 |
| 响应处置 | F31–F32 | 阻断策略、执行记录、恢复及阻断白名单 |
| 报告与导出 | F37–F38 | 报告模板/实例、导出历史与受保护下载 |
| 任务与消息 | F40–F41、F48–F50 | 任务、计划、消息、通知配置和健康异常 |
| 平台管理 | F39、F42–F47、F51–F57 | 审计、个人资料、身份权限、资源范围、系统与运维 |

导航聚合不是修改功能组归属。审计保留于管理入口，但关键对象与动作也提供带上下文的审计跳转。原型追溯按功能组列出全部入口，重点闭环做深；非重点页面明确标为设计范围，不能用空页面宣称覆盖所有交互。

### 3.2 通用交互合同

- 列表包含作用域、筛选、排序/分页、结果总数来源、更新时间。空列表区分“尚无数据”“筛选无结果”“未授权”，不得通过错误文案泄露不可见对象是否存在。
- 详情包含稳定 ID、来源/观测时间、授权范围、证据与相关任务。无来源字段显示“未观测”，不填推断默认值；关系图须有列表替代。
- 提交动作先冻结目标、版本和请求意图。重复点击不能生成第二个副作用；请求结果未知时提供重新查询原请求，不能把再次点击改为新请求。
- 切换租户/域、退出或另一标签换身份时，清理旧身份的私有视图并丢弃过期响应。取消弹层只关闭表单；取消任务必须单独请求并显示确认状态。
- 危险动作展示目标、数量、授权范围、可能影响和恢复边界。响应、凭据、权限类操作不能仅靠按钮颜色或前端禁用承担安全责任。
- 错误保留可用输入并标注安全错误码/关联 ID，不回显密码、令牌或原始目录敏感值。验证失败不得静默降级。
- 任务详情展示实际状态、尝试次数、进度可信性、时间、部分结果与可执行动作。导出“可请求下载”与实际通过实时授权的文件下载分开。

### 3.3 原型验证范围

原型在独立目录实现，使用合成身份/域/资产，常驻“演示数据”标识。原型优先验证接入、调查、检测、响应确认、任务/导出和管理权限路径；不调用生产 API，也不复制真实密钥或账号。

每条重点路径至少检查正常、加载、空态、失败、无权限、结果未知、关闭/返回、重复提交和中途身份切换。桌面宽屏与窄窗口检查表格溢出、弹层焦点、键盘导航、非颜色状态提示和放大阅读。高保真原型确认之后，生产页面实现仍须独立验证。

## 4 架构与模块职责

### 4.1 进程与依赖

沿用 [ADR-001](../architecture.md) 的模块化单体 API + 独立 Worker。现有程序 [cmd/adtr/main.go](../../cmd/adtr/main.go) 提供 api、worker、migrate、bootstrap 模式；HTTP/配置属于 [internal/runtime](../../internal/runtime)，持久化及迁移属于 [internal/store](../../internal/store)。

```text
浏览器 React / TypeScript
          │ 会话、CSRF、严格输入
          ▼
Go API ─── 授权/领域模块 ─── PostgreSQL 权威状态
                                  ▲
                                  │ 队列/租约/审计/结果
                             独立 Go Worker
                                  │ 显式登记执行器
                      受限 LDAP / 后续采集和响应适配器
                                  │ 严格 TLS 与出口范围
                             授权 AD 实验域
```

现有前端使用 React 19.1.1、TypeScript 5.9.3、Vite 7.3.7，版本见 [package.json](../../web/package.json)；服务端按仓库要求 Go 1.27.1。PostgreSQL 17 系列承担权威数据和事务任务队列。搜索/分析存储是否拆出，待 G06 工作负载与查询实测后另作 ADR，不先引入双写。

### 4.2 所有权

| 模块 | 拥有的状态和职责 | 不承担 |
| --- | --- | --- |
| 身份和访问 | 会话、MFA、角色动作、租户/域授权版本 | 信任浏览器声明的 actor/tenant |
| 域和操作账户 | 域配置版本、加密账户引用、显式凭据用途 | 以元数据查看权限代替凭据使用权限 |
| 目录与采集 | 源对象身份、观测快照、采集批次/游标 | 从一次缺席推断删除，或伪造未观测字段 |
| 任务与计划 | 输入冻结、幂等账本、租约、状态、执行历史 | 宣称外部系统恰好执行一次 |
| 检测与规则（规划） | 不可变规则版本、检测输入与发现证据 | 未经 G04 提供规则与预期结果就判定通过 |
| 调查与响应（规划） | 事件、处置意图、逐对象结果与恢复关联 | 直接开放任意命令、URL 或无范围 AD 写入 |
| 报告与导出 | 产物元数据、生成历史、授权读取 | 把浏览器缓存或可猜路径当授权 |
| 审计与运维 | 追加审计、可恢复可见性、健康观测和受限诊断 | 对业务审计无痕删除或返回任意文件 |

模块拥有唯一写入入口不意味着单进程。多 API/Worker 通过事务、租约和 fencing 竞争。未来采集器不得直接连接数据库；跨模块更新由应用事务或受控 outbox 协调。

## 5 数据与接口契约

### 5.1 领域对象

| 对象 | 关键身份及关系 | 设计要求 |
| --- | --- | --- |
| 用户/角色/资源组 | tenant、actor、功能动作、域集合 | 服务端派生身份；撤权使旧会话/工作失效 |
| 域连接/账户引用 | 稳定 ID、配置版本、凭据用途和授权版本 | 诊断授权、目录读取授权分别检查 |
| 目录观测 | 源 GUID/DN、类别、观测时间、任务/批次来源 | 字段未知显式空值；扩展字段版本化 |
| 任务/尝试 | task ID、kind/version、scope、epoch、lease/fence、parent | 输入不可变；重试与恢复保留历史 |
| 检测/发现/事件（规划） | 规则版本/hash、目标快照、源事件与证据引用 | 时间与版本可追溯，规则更新不改历史判定 |
| 响应意图（规划） | 目标、动作、确认依据、外部结果、核对状态 | 成功/失败/不确定逐对象记录，不覆盖旧结果 |
| 产物 | 所属任务、创建人/域快照、版本、摘要、保留状态 | 列表与下载实时授权；结果就绪不等于可下载 |
| 审计事件 | actor、动作、对象、scope、结果、请求/任务关联 | 业务变更同事务追加，未知历史不补造 |

任务、目录观测和凭据使用生命周期有不同的结束条件。任务进入终态不能替代凭据执行结束证明。迁移必须在精确 schema version 和锁顺序下执行，不能通过新文档擅增迁移编号或跨模块写 SQL。

### 5.2 现有接口入口与规划边界

| 现有入口/能力 | 契约 | 本方案的使用边界 |
| --- | --- | --- |
| `/api/auth` | [身份契约](../identity-contract.md) | 本地账户与会话；非 AD SSO |
| `/api/tasks` | [任务契约](../tasks-contract.md) | 只呈现已登记类型，不向原型臆造执行能力 |
| 用户/角色与功能权限 | [访问契约](../access-contract.md) | 所有修改服从当前服务器权限 |
| 租户、资源组、域范围 | [资源契约](../resource-contract.md) | 管理权限与业务域范围分离 |
| 域配置、诊断、账户 | [域契约](../domain-contract.md)、[账户契约](../operation-accounts-contract.md) | 单次诊断与凭据引用都有显式安全边界 |
| `/api/directory/v2/*` | [v2 API](../directory-v2-api-contract.md) | 已有四类扩展事实字段；不是完整资产/关系 API |
| 审计及导出历史 | [审计](../audit-contract.md)、[导出历史](../export-history-contract.md) | 当前 Audit/XLSX 生产者，不泛化为所有业务导出 |
| 系统、计划和运行日志 | [健康](../system-health-contract.md)、[计划](../schedules-contract.md)、[日志](../operational-log-contract.md) | 仅已实现的本地采样/健康计划/诊断包 |

后续检测、图谱、响应、通知与报告接口须在对应功能 Issue 内先定义 schema、权限、版本、错误、任务类型与幂等语义，再接入公共路由。此处不写虚构可调用 URL。

所有输入严格校验，响应不泄露底层数据库错误或凭据。业务时间存 UTC、使用 RFC3339；展示时区及源系统单位仍须 G01 冻结。稳定分页、当前权限过滤和对象版本冲突按既有契约实现，不由 UI 自行拼接全量数据绕过。

## 6 任务与外部副作用

### 6.1 状态与重试

现有权威状态来自 [tasks-contract](../tasks-contract.md)：queued、running、retry_wait、cancel_requested、succeeded、failed、partial_failed、dead_letter、cancelled。

```text
queued → running → succeeded / failed / partial_failed / dead_letter
            ├── retry_wait → queued（仅已登记的可安全重试类型）
            └── cancel_requested → cancelled（收到执行结束确认）
queued / retry_wait → cancelled
```

完成与取消竞态按真实结果记录，并追加 completed-with-cancel-race 事件；它不是新的成功状态。失联的取消不能显示“已取消”。partial_failed 保留逐对象结果；恢复创建关联父任务的新任务并重新授权，不重置原历史。

幂等键作用域为 tenant/domain/kind，同键同规范化输入返回旧任务，输入不同返回冲突。领取不增加 attempt，真正开始才增加；max_attempts 含第一次执行。重投递不能被误算为业务重试。

### 6.2 执行安全

提交、审计、outbox 同事务。数据库状态是权威，通知丢失不丢任务。执行前及各关键阶段检查当前权限、冻结版本和 lease/fence；旧 Worker 回写被拒绝。锁順序和 schema gate 服从现有引擎，不在网络 I/O 期间持有长期授权事务。

现有 infrastructure.health 是可安全重试的基础设施任务；domain.connection_test 是单次不可调度类型，因为认证绑定可能影响远端审计/锁定计数。不能把健康任务的 5 次策略推广到 AD 探测。目录 v1/v2 也必须遵守各自登记的执行、授权及结束证明契约。

AD 写、阻断、恢复、远程执行默认不开放。未来接入前必须确定动作白名单、逐对象账本、预检、超时核对、进程终止和恢复策略；仅有 fencing 只能阻止本地过期回写，不能撤销已发网络数据。

任务成功、产物生成、文件可下载、业务目标完成分别呈现。请求超时后先查询已冻结意图；不得自动生成新幂等键重放危险操作。

## 7 安全与审计

身份 → MFA 状态 → 功能动作 → tenant/domain scope → 当前对象版本/凭据用途构成每个业务路径的授权链。列表、总数、搜索、批量、导出和任务结果都不能旁路。平台管理员没有默认域或凭据使用权限。

现有会话使用 HttpOnly cookie，CSRF/Origin 与严格 JSON 由服务端适配器处理。前端会话重核验和过期响应隔离见[跨标签契约](../session-invalidation-contract.md)。原型中的角色切换只是演示状态，不是安全实现。

凭据由外部密钥加密，传输验证 TLS；LDAP 389 必须 StartTLS 成功后绑定，LDAPS 验证证书链、主机名和有效期。出口目标限定在授权配置，禁止任意 URL/命令形成 SSRF 或远程执行入口。密钥供应商、轮换、灾备恢复仍是部署决策。

审计记录与业务变更同事务；现有触发器保护不等于能对抗数据库所有者。生产仍需分离迁移/运行角色和限制 DDL/TRUNCATE。审计隐藏/还原不等于物理清理；保留期和受控删除路径必须另行评审。

威胁验证至少覆盖跨域对象引用、撤权后执行、同权限重新授予复活旧任务、过期会话、旧租约写回、TLS 降级、凭据泄露、任意路径读取、导出越权及不确定副作用重放。仅使用合成环境开展本次工作。

## 8 Windows 接入与兼容路径

后端 Go 服务与 Windows 采集端是独立兼容问题。2008 原版与 2008 R2 分别验收；现代服务端构建成功、交叉编译或合成 LDAP 测试都不证明老 Windows 可用。

优先评估受支持主机上的远程采集网关；确需本机安装的路径另定受该 OS 支持的工具链、签名、依赖、补丁和 TLS 安全策略。两者的业务差异须记录，不能把远程网关宣称为等价本机采集器。

G05 覆盖 Windows Server 2008、2008 R2、2012、2012 R2、2016、2019、2022、2025，每版安装卸载、身份权限、证书连接、事件采集、资产同步、断线恢复、重启升级、资源压力、审计错误九类，共 72 个场景槽位。场景细化、实验机、凭据和授权待提供；当前没有真实槽位验收。

旧系统若不能满足强制安全基线，应保留为明确阻塞并由负责人决定支持路径，不通过关闭证书校验或降低安全策略补齐绿灯。执行真实实验需独立授权，不使用生产 AD。

## 9 非功能目标

以下是验收维度和测量办法，不是已批准数值或 SLA。现有任务超时、分页上限等实现限制继续按各自契约执行，不能被本表改写。

| 维度 | 必须冻结的输入 | 验证方法 |
| --- | --- | --- |
| 容量/吞吐 | 域数、DC/资产数、事件速率、并发用户、规则规模、峰值倍率 | 代表性合成集与授权实验集分别测，记录硬件、版本、数据和瓶颈 |
| 延迟/新鲜度 | 搜索、页面、任务排队、采集到发现的目标及分位数 | 从端到端时间戳测量，区分等待/执行/刷新 |
| 可用性/恢复 | 服务目标、维护窗口、RPO/RTO、备份保留与恢复权限 | 故障注入、备份恢复演练和恢复后完整性核验 |
| 存储/保留 | 原始事件、观测、规则、任务、审计、产物各自期限 | 增长曲线、边界清理、引用完整性及法律/审计要求复核 |
| 扩容/隔离 | API/Worker 数量、域公平性和资源配额 | 并发领取、故障域隔离、长稳与回压测试 |
| 浏览器体验 | 浏览器支持矩阵、最低窗口尺寸、辅助技术目标 | 真浏览器、键盘/焦点、放大、长文本和状态反馈测试 |
| 运维可观测 | 指标/日志保留、告警负责人和通知渠道 | 缺失、陈旧、失败明确展示；告警回路演练 |

数值由 G06 与业务负责人确认，实测未达标时保留差距和改进计划，不倒改目标。存储/查询架构扩展必须由测量推动。

### 10.1 测试分层

1. 静态/单元：格式、类型、输入边界、状态机、权限默认拒绝、需求完整性。
2. 持久化：真实 PostgreSQL 的迁移、事务、租约竞争、撤权、幂等和恢复。
3. 服务链：实际 API/Worker 进程及合成 TLS LDAP，验证启动、断线、崩溃和受限出口。
4. 浏览器：真实界面与服务连接，含中断、重复点击、会话切换、返回/取消和权限错误。
5. 授权实验室：真实 AD 和八版 Windows，源字段、算法判定和副作用核对。
6. 生产发布前：容量长稳、恢复、安全审查、签名/安装与操作手册。

仓库现有入口为 `make check`、`python3 scripts/test_integration.py`、`python3 scripts/test_auth_e2e.py` 及其套件、`python3 scripts/test_lifecycle.py`。缺少 Docker、浏览器或授权实验环境必须记录未运行/阻塞；不能跳过算通过。

每个 PR 记录精确 head、实际命令、检查结果、独立审查、风险和未完成项。CI 成功、合并、原型确认和产品验收四者互不替代。本方案不授权合并或生产部署。
