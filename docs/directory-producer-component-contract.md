# F12 directory executor and observation staging

Current local integration status (2026-10-07): migration15, production registry/HTTP/task-authority wiring and default-denied purpose APIs are now present in source. The compiled consumer capability is true, while the independent deployment switch remains defaultfalse. The component-stage limitations below describe their original checkpoints; actual PostgreSQL, browser and AD execution remain unverified. Current UI contract: [directory-api-contract.md](directory-api-contract.md).

Local components follow the separately typed task authority checkpoint. `DirectoryKind` defines a single-attempt, nonreplayable and nonschedulable task with a125-second outer timeout. It is now registered by the API/worker, with migration15 installing its schema. The independent deployment flag remains defaultfalse; registration alone does not grant credential use.

The first fenced transaction rechecks current directory purpose/source/pair/policy authority, opens the exact ledger and copies envelopev2. Decryption occurs only after that transaction returns known success. Owned ciphertext, plaintext and password buffers are cleared on failure, cancellation and panic. The real `ReadDirectory` primitive rechecks authority in fenced transactions for each stage/page and final return. Progress is bounded independently of page count. Generic task result/checkpoint objects remain empty.

Version1 security caps are10,000 objects,100 pages,1,000 entries/page,16MiB encoded object/cookie budget and64KiB cookies. These are provisional safety caps, not source capacity acceptance. The complete stored JSON has its own16MiB limit including metadata/array overhead, so an observation near the transport cap may be rejected before insertion. Rejection never publishes partial objects.

Successful transport normalizes the RootDSE host and stages the entire dictionary-validated, domain-scoped observation in a final live-authorized fenced transaction. Publication stores canonical bytes, count and SHA-256 under immutable task identity. The migration15 SQL guard requires running state, a live lease, the exact opened ledger/opener and current authority; update/delete/truncate are refused. Data is bounded and validated again on decode, including a per-object raw cap before typed allocation, exact digest/count, dictionary fields, DN scope and canonical byte equality.

Staging and task Finish are separate. Cancellation after staging must remain invisible: every future observation read must join the task and require `state='succeeded'`, plus current domain/data permissions and source/policy visibility. The dedicated observation route implements that succeeded/current-source/policy gate and live data-reader scope. The database/browser scenarios remain unexecuted locally.

Executor tests explicitly stub transactions for opening/commit/credential/authorization failures and exercise the real reader's initial authorization rejection before I/O. They do not prove a successful executor→reader→database publication. Snapshot tests cover normal/empty data, absent-vs-zero values, malformed/corrupt bodies, RootDSE case/root-dot normalization, domain escapes and aggregate budgets. PostgreSQL trigger/race tests and successful full producer/browser/AD execution remain required.

Local evidence: complete `make lint test build` passed (all Go packages under race/vet/build, formatting/requirements checks and nine Python contracts); all-package integration-tag compilation/vet passed. Independent source review verified the RootDSE normalization fix and reported no remaining confirmed production defect. Actual PostgreSQL/AD/browser and successful full producer execution remain unverified.
