# 域列表页序号契约（UI-0390，本地候选）

## 来源与范围

Issue [#16](https://github.com/yunpiao/adtr/issues/16) 原行列出「序号 type=index」。
本仓库 [domain-contract.md](domain-contract.md) 的 UI-0390 明确采用
“Paged connection row index from actual page offset”。此次实现遵循已冻结的本地分页
契约；原行本身不足以证明旧系统跨页计算行为，未声称完成源运行时兼容性验收。

候选从 #296 head `21fcba85fb057a1327be33955edd0d8aa84f416e` 重建；
只增加域列表的展示列及对应测试，不修改请求参数、接口、权限、认证或 CSS。

## 展示规则与身份边界

- 「域名」后增加「序号」列，表头使用 `scope="col"`，单元格使用
  `data-label="序号"`，沿用既有表格及窄屏标签规则。
- 按当前成功响应 `List` 的原始顺序展示，零基行索引为 `index` 时，序号为
  `(read.data.page.pageIdx - 1) * read.data.page.pageSize + index + 1`。
  两个分页值必须来自同一份实际响应，不能采用尚未提交的表单草稿或请求页码。
- 序号是当前查询结果的位置，不是域身份，也不稳定跨查询保存。筛选、排序、重置、
  翻页或服务器返回顺序变化后，以新响应重新计算。草稿编辑不改变已展示序号。
- React 行 key、详情参数、按钮 `data-domain-id` 和返回列表的焦点恢复仍使用
  `domainId`。域 ID 完整显示，不以序号替换。
- 空列表无虚构编号；读取中隐藏旧表，读取失败清除旧数据。旧请求在查询、身份变化
  或卸载后迟到不能恢复旧编号，沿用现有请求代际隔离逻辑。

没有新增配置参数或功能开关。响应页码、页大小是计算实际分页偏移所必需的数据；
删除偏移会导致每页从 1 重复编号，使用草稿会使未提交操作改变已有事实。
新增列会占用横向空间，窄屏和视觉布局必须另行检查；DOM 断言不能证明像素表现。
