# ADR-001：工程底座与安全边界

状态：可用于 G03 工程骨架的决策；业务字段与逐任务策略待 G01 输入。
关联：[#2](https://github.com/yunpiao/adtr/issues/2)、[#3](https://github.com/yunpiao/adtr/issues/3)。
产品功能验收：0/209。本文件描述设计，不是已实现能力。

## 技术选择及所有权

采用模块化单体 API + 独立 Worker；首期避免过早拆分微服务。
服务端选择 Go 1.27.1，前端目标为 TypeScript/React（版本及锁文件在引入时固定）；
首个工程骨架只提供健康探针，不伪造前端业务页面或占位业务 API。
PostgreSQL 为唯一权威存储，任务队列也使用事务表与租约；不额外引入 Redis 队列造成双写。
开发数据库选择 PostgreSQL 17 系列；实际镜像需在编排引入时固定可验证 digest。
搜索、分析型存储在容量与查询语义确认后单独 ADR，不承诺未知吞吐量。

| 边界 | 所有者与约束 |
| --- | --- |
| 浏览器 | 展示、表单与交互；不能决定身份、租户或授权范围 |
| API | 会话验证、MFA 状态、租户/域授权、输入校验、事务提交与审计；不执行耗时采集 |
| Worker | 领取已授权任务，在执行时重新检查授权/凭据版本；持久化结果、游标和审计 |
| 采集接入 | 每个安装实例有独立身份和作用域，批次去重，拒绝客户端伪造租户/域 |
| PostgreSQL | 模块拥有自己的写入接口；跨模块变更通过事务应用层或 outbox；不允许采集器直接写数据库 |
| 外部 AD | 只经受限适配器访问；开发默认无凭据、无连接、无 AD 写能力 |

单写者指数据模型有唯一写入模块，不指只有一个进程。API 可多副本；Worker 可多副本，
每个任务领取由行锁、持久化租约与 fencing token 决定。定时计划通过
`(tenant_id, schedule_id, scheduled_at)` 唯一键产生一个逻辑任务。
单机开发为 API/Worker/数据库独立进程；跨主机保持同样契约，
使用受验证 TLS、私有网络与外部密钥机制，数据库高可用不在 G03 宣称完成。

## 身份、资源隔离与审计

所有业务路由默认拒绝，必须通过身份、MFA 要求、权限动作、租户和域四层验证。
仅明确登记的 `/livez` 和 `/readyz` 为无敏感信息的基础设施探针；它们不提供业务数据。
角色初步分为只读调查、规则管理、响应操作和平台管理；最终权限矩阵在身份/权限 Issue 中冻结。
平台管理身份不隐含所有 AD 域的操作授权。数据库查询必须携带服务端确定的 tenant/domain scope；
对象读取、搜索、导出、批量操作、任务结果均使用同一授权入口。
客户端提交的 actor/tenant/role 字段不能覆盖会话身份。
MFA 恢复、提权、AD 写操作需显式授权与新鲜验证；机制选型不等于认证功能已实现。

状态变更与审计在同一事务落库，审计包含 actor、作用域、动作、对象、结果、关联请求和任务版本。
API/Worker 的业务数据库角色不得 UPDATE/DELETE 审计记录；保留期删除仅由独立受控流程执行并留证。
普通管理员没有静默删除审计的产品接口。外部副作用先持久化意图，再执行，
结果不确定时标记待核对，不能把超时等同于失败后直接重试危险写操作。

## 凭据、网络和错误

运行时凭据由环境或只读密钥挂载注入，不提交默认密码。
AD 凭据存储采用外部管理的密钥加密、独立密钥标识、可轮换版本与最小访问范围；
日志及 API 错误不输出凭据、连接串或 AD 原始敏感值。
具体 KMS/provider 是部署输入，未配置时相关功能必须拒绝启动或拒绝操作。
LDAP 389 只允许先成功 StartTLS 再绑定；禁止明文 simple bind。
LDAPS 636 必须验证证书链、主机名与有效期，不允许 insecure skip verify。
TLS 或凭据错误停止任务并产生可解释错误，不降级、不自动反复重试。
域/DC 地址由授权域配置解析，禁止任意 URL 触发 SSRF；证书名称以配置的 DNS 身份验证。
新增域必须真实事务持久化并可被同步任务读取，不能以空 success 代替保存。

## 规则与兼容性

规则草稿 → 生成候选 → 在可判定夹具中真实执行 → 审核发布不可变版本 → 任务引用版本/hash。
运行中任务不得隐式切换规则版本；回滚创建明确的新发布指针，历史证据保留原版本。
专项团队提供的算法、规则及预期结果是外部输入，空规则库不能通过规则验收。

Windows Server 2008 原版与 2008 R2 分别建实验矩阵。现代 Go 服务端不代表旧 Windows 采集器兼容。
优先评估受支持主机上的远程采集网关；必须本机安装的路径需单独选择受该 OS 支持的工具链，
评估补丁、签名、TLS 和依赖风险。两条路径均须真实实验机验收，不能用交叉编译代替。
2008/2008 R2/2012/2012 R2/2016/2019/2022/2025 各建 9 类实验：
安装卸载、身份权限、证书连接、事件采集、资产同步、断线恢复、重启升级、资源压力、审计错误。
共 72 个场景槽位，详细步骤/夹具/预期结果与工具链由 G05 冻结；当前无任何槽位算通过。

## 威胁与验证边界

| 威胁 | 控制 | 必须验证 |
| --- | --- | --- |
| 跨租户/域对象引用 | 服务端 scope + 查询约束 | 直接对象、搜索、批量和导出越权 |
| 被盗会话/提权 | MFA、新鲜验证、最小角色 | 失效会话、撤权、恢复流程 |
| LDAP 降级/MITM | 强制 TLS、证书严格校验 | 过期、错主机、不可信 CA、StartTLS 拒绝 |
| Worker 重投递/失效租约 | 去重、fencing、幂等账本 | 重复消息、租约过期、旧结果回写 |
| 凭据泄露 | 外部注入、加密和日志脱敏 | 错误栈/URL/导出中不泄露密钥 |
| 响应动作滥用 | 授权实验域、动作范围、审计 | 未授权写操作零外部副作用 |
| 规则注入/远程执行 | 有限执行器、资源预算、发布审核 | 超时、逃逸输入、不可变版本 |

真实 AD、外部通知、生产发布均未获本次执行授权；开发与 CI 只能使用合成数据及本地夹具。
