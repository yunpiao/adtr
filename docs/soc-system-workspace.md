## 参数与失败恢复

`expectedRevision` 是必需 CAS 参数，防止用户基于旧版本覆盖他人修改；省略或非法值被服务器拒绝，过旧版本返回 revision_conflict。副作用是并发写入后必须先重新读取，再决定新的修改，不能自动盲重试。85–90 是当前明确的本地告警策略约束，不代表清理或外部通知。

`instance=local-api` 与磁盘历史的 `storageId` 限定已登记目标，防止把用户输入当作任意文件路径；磁盘历史需要 storageId，CPU/RAM 不需要。`startTime/endTime` 是必需 UTC 秒时间窗，最长 24 小时；删除/越界会被 API 拒绝。更长时间窗会返回更多实际点和缺口，但不制造此前不存在的数据。

读取失败清除旧结果；暂时网络/5xx 按至少 5 秒间隔自动重读，权限拒绝不自动重试。刷新可恢复读取。未知结果或 CAS 冲突停止写入重试、清空证明字段，要求重读服务器版本；新请求仍需新鲜 MFA 与当前密码。取消等待不保证撤销已提交修改。API 可选 reason 字段只接收字符串，格式异常整份响应拒绝展示。各已知原因翻译保留依据，不把建议写成已验证根因。

## 固定 UTC 历史时间窗（Issue #280）

工程 [#280](https://github.com/yunpiao/adtr/issues/280) 补齐 AD-F-200 已有
`startTime/endTime` 秒参数的页面输入（原工作簿第 204 行、FLD-3210/3211，
FLD-3212 为指标）。UI-0656/0657 只证明原时间下拉，不能作为旧自定义日期
控件的 1:1 复刻证据。本切片不改变 API、权限、采样、保留期或产品验收 0/209。

资源页保留四个服务器时钟驱动的滚动窗口，另可选择“固定 UTC 时间窗”。
两个输入明确要求 `YYYY-MM-DDTHH:mm:ssZ`，不接受本地时间、时区偏移、小数秒、
空白或不存在的日历日期。UTC 文本不依赖浏览器本地时区，1970-01-01 起的非负
整秒有效；起点必须早于终点，最长 86400 秒，终点不包含。

选择固定选项、编辑或清空输入仅改变草稿。只有显式“应用固定时间窗”才改变
已应用查询；非法草稿保留原确认窗口和结果。页面分别标明当前已应用模式与
草稿，避免把尚未提交的输入视为正在显示的结果。重复提交同一有效窗口重新读取。
提交前使用最近成功读取的服务器 `checkedAt` 保守检查未来时间：若结束时间
比该检查晚，先刷新取得新的服务器时间再提交；不按本机时间推算或放宽上限。
每次实际历史请求仍由服务器数据库当前时间最终裁决，包括服务器时钟回退时。

固定模式的手动刷新、原 15 秒轮询、指标和已登记磁盘目标切换均保持确认起止；
刷新仍读取最新当前资源和存储注册信息，当前指标不是固定窗口终点快照。
切回任一滚动选项立即恢复随服务器检查时间前移。历史结果仍只包含窗口内真实
持久化样本，空窗统计为 null，缺口不补零或插值。读取失败清除结果；暂时失败
沿用原轮询恢复，权限/会话拒绝不自动重试，旧查询的迟到响应不得覆盖新查询。
离开或重新进入面板、页面 reload、Back/Forward 沿用现有挂载生命周期，重新
以默认滚动 15 分钟开始。没有 URL 查询参数、localStorage 或持久化查询承诺。

`startTime/endTime` 是历史 API 必需参数，解决复查同一半开时段的问题；删除或
越界由 API 拒绝。固定模式仅在需要跨刷新复查同一时段时使用，副作用是新采样
不会自动出现在旧窗口，必须应用新时段或切回滚动。`storageId` 仍只在磁盘指标
必需且只来自服务端登记列表；删除会拒绝磁盘查询，CPU/RAM 不携带该参数。
本切片无新增部署配置。E2E 的 `timezoneId=Asia/Shanghai` 仅用于证明非 UTC
浏览器输入的时区独立性，删除将失去该覆盖，不影响产品时钟；副作用仅是该测试
上下文的本地时间格式变化。安全截图新增 fixed-history 桌面/390px 两张，合计
12 张，仍沿用只读捕获、来源散列和运行 provenance，不提高时间/重试预算。

候选新增 DOM/UTC 边界、草稿、固定刷新/轮询、目标、读取失败、迟到结果和生命周期
检查，原生 E2E 增加真实样本半开边界、统计和固定视图。具体本地命令及精确 head CI
