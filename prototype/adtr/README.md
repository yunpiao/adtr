# ADTR 高保真交互原型

独立、零运行依赖的企业安全控制台。所有身份、域、资产、事件、任务与下载内容均为合成数据；没有生产 API、真实 AD、外部通知或真实响应效果。数据只存在当前浏览器页面内存，刷新会重置。

关联 [Issue #87](https://github.com/yunpiao/adtr/issues/87)。总体方案 [PR #88](https://github.com/yunpiao/adtr/pull/88) 已按用户授权合入 main，设计基线为 [`5ca5ea513933d673ef87613fd0a863500a50b92a`](https://github.com/yunpiao/adtr/commit/5ca5ea513933d673ef87613fd0a863500a50b92a)。本原型仍待独立审查、精确提交浏览器验证及用户原型评审；没有合并或部署授权。产品验收维持 **0/209**。

## 打开原型

直接双击 [index.html](index.html)，与 `styles.css`、`app.js`、`coverage.js` 放在同一个目录。使用 classic scripts，无模块导入、fetch、远程字体或资源；按设计支持 `file://` 打开，此路径也纳入真实浏览器验证脚本。

规范测试使用本地 HTTP。以下是实际文件对应的启动方式，不代表已在所有环境验证：

```sh
# 在仓库根目录执行；只监听当前电脑回环地址
python3 -m http.server 8765 --bind 127.0.0.1 --directory prototype/adtr
# 浏览器打开 http://127.0.0.1:8765/
# Ctrl+C 停止服务器
```

不需要 `npm install` 或构建步骤来浏览原型。不要提供真实密码、MFA 秘密、邮箱、手机或 AD 地址；域配置只接受保留的 `*.example.test` 名称。没有公开托管或部署。

## 推荐体验顺序

1. **安全总览 → 目录资产**：按名称、类型、风险筛选，打开资产详情，查看合成成员关系、缺失字段和关联事件。
2. **AD 接入**：保存合成域配置，确认它不会自动获得数据授权；运行单次演示诊断。目录 v2 必须同时勾选总开关、v2 附加开关和独立用途授权。
3. **检测与规则**：选择固定版本模板，提交任务，在“任务与消息”看排队、运行和合成结果。双击/重复 Enter 不应产生重复任务。
4. **威胁调查 → 响应处置**：从事件进入响应，例如 e2 必须保留 `demo.service / a4`，e3 必须保留 `DEMO-Tier0 / a3`。确认绑定精确事件、对象、GUID、版本、域与当前授权版本。
5. **报告与导出**：提交导出任务，离开后找回，下载带 `SYNTHETIC` 标识的 CSV；撤销演示下载权限后，切域再返回不能恢复旧授权。
6. **平台管理**：修改另一自定义角色的读写矩阵；写权限依赖读权限，保存需要演示确认。查看按当前域隔离的操作审计。

顶部可切换“安全运营员”“只读调查员”“平台管理员 · 无域授权”和显式授权域。切换时清除旧弹层、选择和草稿；平台管理员没有默认 AD 域读取权。

桌面顶部“演示场景”支持空数据、读取失败、无权限、陈旧观测，以及任务失败、未知结果、部分失败、取消竞争、停止未确认。任务类场景在提交时冻结，只影响后来提交的合成任务。窄屏为可读性隐藏场景控制器，主业务路径仍可操作；测试窄屏前可先在桌面设定场景。

## 状态和授权边界

- 任务只模拟页面状态；`unknown` 是原型的“结果待核对”展示，不注册生产任务状态。核对固定夹具不会再提交任务。本轮保守拒绝旧授权版本核对，即使稍后重新授予同名角色。
- 单次连接诊断和响应没有通用恢复入口，包括手动 recover。可恢复的合成检测/导出/健康类型创建有父任务 ID 的新任务，原历史保留。部分失败不支持整批恢复。
- 排队取消不增加尝试；运行取消先显示请求；竞争可能保留成功并记录 `completed-with-cancel-race`；失联显示 `cancellation_unconfirmed`，不能伪称已取消。
- 权限选择器统一限制列表、数量、详情、审计和导出。无权限场景下后台 tick 不得重新插入被拒绝的详情。确认快照失效后禁止提交。
- 下载撤权持续到整个演示页面重置，导航和切换场景不会恢复。生产切片中的真实 Audit/XLSX 与本原型 CSV 完全分开。
- 目录 v2 需要总开关、附加开关和独立授权同时满足。未知字段显示“未观测/未采集”，不填零；本地合成批次不是 AD 时间点快照。
- 健康计划定义不可原地修改，变化须另建经授权的计划 UUID；本轮仅展示说明，没有计划执行器。可恢复归档不等于物理清理或释放磁盘。
- 没有真实身份验证或安全机制。跨标签通知仅为重核验提示的预留实现，尚无完整跨标签身份场景验收，不据此声称生产会话安全。

## 可复现检查

零依赖静态与受限 Node VM 回归：

```sh
node prototype/adtr/test-static.cjs
```

浏览器测试复用仓库已有 `web/package-lock.json` 锁定的 Playwright 1.56.1，不更改生产前端文件：

```sh
npm ci --prefix web
(cd web && npx playwright install --with-deps chromium)
node prototype/adtr/test-browser.cjs
```

有现成工具时可以指定来源，无需重复安装：

```sh
PLAYWRIGHT_MODULE_PATH=/absolute/path/to/playwright \
CHROMIUM_EXECUTABLE_PATH=/absolute/path/to/chromium \
node prototype/adtr/test-browser.cjs
```

脚本自建随机端口回环静态服务器，运行后关闭 browser/server；每个场景使用独立浏览器 context。只允许应用本地静态资源请求，出现外网/API 请求或页面 JS 错误会失败。失败也写报告和失败截图，缺浏览器计为阻塞且非零退出。

输出在 `prototype/adtr/test-results/`，包括 JSON 报告、四张代表截图及必要失败截图。报告记录源文件 SHA-256、`GITHUB_SHA`（CI checkout）与 `GITHUB_HEAD_SHA`（PR head）；不能用不同提交的结果作为验收证据。该目录是运行产物，默认不跟踪提交。

目前本地 18 项静态/VM 检查通过；本地 Chromium 因执行器 socket/挂载限制未运行成功，云浏览器也未能到达该执行器的回环预览。真实浏览器结果须以独立原型 CI 的精确提交报告为准，详见 [validation.md](validation.md)。未提供虚构截图，未声称键盘、窄屏或 33 个浏览器场景已通过。

## 文件结构

- `index.html` / `styles.css` / `app.js`：独立页面、视觉和内存交互，无运行依赖
- `coverage.js`：完整需求与局部模拟范围
- `interaction-plan.md`：原型整体设计和后续目标
- `test-static.cjs`：语法、范围与核心授权/任务 VM 回归
- `test-browser.cjs`：实际 Chromium 行为、文件直开、网络边界与截图
- `validation.md`：已执行证据、剩余验证和限制

代码只在 `prototype/adtr/`。独立原型 CI 在专用 workflow 中运行，不调用生产应用。原型评审、实现审查、CI、合并、部署和产品验收分开记录；本次不自行合并、部署或关闭 #87。
