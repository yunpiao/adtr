# ADTR 产品交互原型

独立、零运行依赖的企业身份安全控制台。所有账户、域、资产、事件、任务、通知、许可和下载内容均为合成数据；无生产API、真实AD、外部通知或系统变更。数据只存在当前浏览器页面内存，刷新会重置。

关联 [Issue #87](https://github.com/yunpiao/adtr/issues/87) / [PR #89](https://github.com/yunpiao/adtr/pull/89)。总体方案 [PR #88](https://github.com/yunpiao/adtr/pull/88) 已按用户批准合入，基线为 `5ca5ea513933d673ef87613fd0a863500a50b92a`。原型PR保持draft等待用户评审，未合并；原型交互不代表209项产品验收。

## SOC 工作流改版

用户再次要求借鉴成熟安全产品后，界面改为工作台优先队列、快速研判抽屉、持续调查工作区、证据关联和响应闭环。49 个业务子页保留在当前一级导航下，管理配置折叠；页面数量不再作为体验完成的依据。

官方参考、设计取舍与验收门槛见 [SOC 重设计](docs/soc-redesign.md)。调查可通过 `#/threats/investigation/e2` 直达；选择实体不改变事件响应目标，响应前明确展示目标和影响；未知结果必须先核对原任务。数据仍为合成的页面内存，刷新保留路由但不会持久化调查记录或用户操作。

本轮精确 head 的浏览器回归与截图以 PR 描述及 Actions artifact 为准，用户尚未验收。原型分支已同步已合入的生产基线，原始方案基线仅作历史记录。

## 功能覆盖补齐（前一轮）

上一版只有九个一级页面，大量需求缺少业务入口，且页面夹杂实现和验收说明。用户试用反馈后，本轮补充业务二级导航、专属页面/详情/配置与状态，把设计审查内容留在文档。不能用209条映射、总页面数量或旧33个测试替代真实功能覆盖。

实际逐项覆盖以 [逐项覆盖矩阵](docs/coverage-matrix.json) 和 [本轮交互边界](docs/workspace-revision.md) 为准：需要指出每项需求的用户入口、操作、结果和模拟边界。页面可浏览、有本地交互、真实外部执行是不同层次，最后一项不在本原型范围。

## 打开与使用

保留本目录所有HTML、CSS、JS运行文件，直接打开 `index.html`。使用classic scripts，无构建或运行依赖、fetch、远程字体或资源。规范测试使用同源回环HTTP；file直开也纳入浏览器回归。

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory prototype/adtr
# 浏览 http://127.0.0.1:8765/，结束按 Ctrl+C
```

不要输入真实密码、MFA秘密、访问令牌、许可或联系方式。联系人仅使用 `example.test` 地址，操作账户使用预置DEMO引用。模拟认证不会建立真实会话或凭据。

顶栏保留当前域选择；“演示环境”入口提供角色和异常场景切换。切换上下文应清除旧弹层、选择和草稿。无域平台管理员不默认获得AD数据访问，只读身份不能提交写操作。

## 主要工作空间

- AD接入：域与数据源、账户用途、部署检查、采集器注册/升级、日志流量、运行保护、远程通道、配置同步。
- 目录资产：对象列表与详情、同步批次、权限变化、敏感资产、行为关系、信任关系和风险记录。
- 检测与规则：基线/漏洞/凭据风险、行为关联、规则条件与测试发布、学习配置、模板和例外。
- 威胁调查：事件证据、攻击路径、行为事件、高级查询、蜜罐与特权账户。
- 响应处置：精确对象确认、策略、响应白名单、执行和恢复历史。
- 报告与导出：模板、类型化报告实例、报告预览、历史下载，以及原有受范围限制的异步CSV。
- 任务与消息：任务状态/取消/恢复、周期计划、通知配置/接收人、运行健康。
- 平台管理：个人/账户/MFA、用户/角色/资源、审计、集成、系统资源、许可、设置、服务、诊断与部署。

这份目录只说明信息架构；各细项深度由实际代码和覆盖矩阵验证，不等于所有业务规则已完整实现。

## 重要回归

- 调查e2到响应必须保留 `demo.service / a4`，e3保留 `DEMO-Tier0 / a3`，冻结域、事件、对象和版本。
- 已提交任务保留模板与输入快照；重复点击不重复创建；未知结果不自动重放；旧授权版本不得重新取得有效性。
- 排队取消与运行取消不同；单次动作无通用恢复；多对象部分失败不得伪造整批恢复。
- 列表、详情、计数、审计和下载始终按同一范围过滤；下载撤权不因切页/切域恢复。
- 新业务动作应改变对应对象或结果而非只弹成功提示；取消编辑/确认不得保存；领域不适用动作不能仅改为“已完成”。

## 检查与证据

```sh
node prototype/adtr/test-static.cjs
# 使用web/package-lock.json锁定的Playwright：
node prototype/adtr/test-browser.cjs
```

`test-browser.cjs` 检查原有安全/任务闭环、新业务路由、领域状态流、无开发注释、桌面/390px布局、键盘/历史、file直开和静态请求边界。每次执行输出 `test-results/report.json`、真实截图与失败证据。报告记录所有运行文件哈希、PR head和CI checkout SHA。

本地浏览器执行限制与历史结果见 [validation.md](validation.md)。最新精确head的真实结果和截图以PR内CI链接及artifact为准；未执行、失败和通过分开记录。最终需要独立审查实际diff、页面覆盖和图像，不能只依靠脚本自报。

## 文件与发布边界

- HTML/CSS/JS：隔离产品界面和内存状态，数据定义与领域操作分别组织。
- 覆盖/交互文档：需求追溯、模拟范围、设计假设和未覆盖项，不进入产品UI。
- 静态/浏览器脚本：回归、同源静态测试服务和截图。
- `.github/workflows/prototype.yml`：专用最小权限QA，使用标准runner，不修改生产应用或全局工程CI。

现有私有预览由单独发布流程维护，同一项目仅在精确版本测试后更新。本原型不执行生产部署，不关闭产品验收需求，不自行合并PR。
