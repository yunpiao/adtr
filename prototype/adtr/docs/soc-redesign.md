# SOC 工作流重设计

## 评审起点

用户在试用后再次明确表示原型不满意，希望借鉴其他安全产品。49 个业务子页及 67 项浏览器检查仅说明功能入口与部分交互回归存在，不代表产品体验通过评审。本轮重做工作流和视觉层级，既有需求映射、权限边界与任务状态机继续作为防退化基础。

## 核心设计原则

1. **先处理待办**：工作台首屏展示优先队列与待核对响应；风险趋势和覆盖统计降为次级。指标点击必须带入对应筛选。
2. **保留分诊上下文**：告警表统一搜索、风险/状态筛选、排序、可删除筛选标签和紧凑行。抽屉用于快速研判；返回恢复队列条件、滚动和焦点。
3. **调查是持续工作区**：事件 ID、域、对象、状态与负责人固定可见。关系、证据、时间线、响应记录围绕同一事件，不以换页或覆盖抽屉丢失上下文。
4. **关系由证据支撑**：所选实体与证据、时间线联动；至少不同事件体现不同关系。无依据的边不推断攻击成功；同名跨域对象按稳定身份区分。
5. **动作有明确结果**：响应保留既有目标/策略版本快照与确认步骤。执行中、已完成、失败、未知结果分别呈现；未知不算成功，恢复需独立追溯。
6. **管理让位于运营**：配置折叠到次级导航，但不删功能或绕过权限校验。业务页面逐步统一表格与详情结构，不把所有功能平铺到首屏。
7. **手机另行组织**：导航可收起、单列待办、调查提供可用文本关系；表格在自身区域滚动，不用隐藏页面溢出掩盖布局问题。

## 实现和验证边界

先实现工作台与调查两个真实样板，以实际浏览器截图和贯穿流程内部评审，再统一其他业务页面。评审需同时考察可用性与视觉层级，不能以测试数量代替质量判断。

必须保留既有授权选择器、跨域隔离、白名单拒绝、重复提交保护、任务状态和确认快照。新增调查上下文在切换域或身份时清除；后退、前进、取消及背景刷新不应打断当前操作。

本轮仍为合成数据的交互原型，不接真实后端、AD 或外部响应系统。用户尚未验收这一设计方向；真实浏览器结果、截图和剩余限制在验证记录中另行注明。
